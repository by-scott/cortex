# 1.6.8 Release Audit

This is the working truth table for the `v1.6.8` release target. It is not a
release note and not a marketing claim. Each row maps to one required review
area from `docs/roadmap.md` and records the current evidence, the verification
surface, the remaining gap, and the `1.6.8` disposition.

Status meanings:

- **Surface present**: code and tests already expose a relevant contract, but
  the release review must still verify limitations.
- **Partial**: part of the contract exists and has acceptance evidence, but the
  remaining limitation must stay public and must not be promoted as a completed
  release claim.
- **Release blocker**: the area lacks a required runtime contract or acceptance
  proof and must be completed before `1.6.8` ships.

## 1.6.8 Patch Evidence

`v1.6.8` keeps the `1.6` harness contract and ships a local vLLM streaming
compatibility patch for hidden-thinking turns:

- OpenAI-compatible parsing now treats `reasoning` and `reasoning_content`
  payloads as visible answer text when provider thinking has been explicitly
  disabled. This fixes Qwen3/vLLM streams that return reasoning deltas but no
  content deltas after `chat_template_kwargs.enable_thinking=false`.
- Shown-thinking mode remains unchanged: provider reasoning is still normalized
  into Cortex `<think>...</think>` output when the operator enables thinking
  output.
- The TPN streaming boundary now filters `<think>...</think>` incrementally,
  including tags split across chunks, instead of suppressing all streamed text
  until the final response is available.
- Focused tests cover reasoning-only non-streaming responses, reasoning-only
  streaming deltas, split think-tag filtering, and hidden-thinking turns that
  still pass a streaming callback to the provider.
- Local vLLM smoke testing against the configured Qwen3 endpoint returned `OK`
  through both direct OpenAI-compatible calls and the Cortex HTTP/SSE turn path
  after the provider thinking parameter was corrected to
  `chat-template-enable-thinking`.
- The SDK release cadence remains independent; `cortex-sdk` stays `1.6.4`.

The `1.6.7`, `1.6.6`, `1.6.5`, `1.6.4`, `1.6.3`, `1.6.2`, `1.6.1`, and `1.6.0`
evidence lines remain part of the current release history: memory extraction
completeness, Telegram/QQ `/think` controls, vLLM thinking request mapping,
plugin minimum-version compatibility, default-hidden thinking controls,
embedding credential propagation, model-specific token-limit inference,
protected-root governance, channel permission correction, plugin effect
accuracy, cache-friendly Executive assembly, provider cache token accounting,
journal/replay persistence hardening, task/goal runtime state, ACP client
support, and release-gate Docker authority are not weakened by `1.6.8`.

## Release Audit Requirements

Before `v1.6.8` can be cut:

1. Every **release blocker** row must be implemented or explicitly reclassified
   with code evidence, test evidence, documentation, and a limitation statement.
2. Every **partial** row must have an acceptance test proving the release claim
   or a public limitation that prevents overclaiming.
3. The release report must include the final state of this table, the strict
   Docker Compose gate result, and behavior/safety/replay/soak evidence.
4. No P2 claim may be promoted to README or release notes unless the relevant
   audit row is no longer partial or blocked.
